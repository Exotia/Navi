# SP11: Ground-Station NAV Row, `goal_relay` and Plan Drawing — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Every task is one commit; never push.

**Goal:** The operator types or clicks waypoints into a NAV row, presses **Go**, and the rover drives them — with the mission state machine on the primary told the truth, so the coordinator's LEDs and the ERC-visible state say `Autonomous` while it happens. Progress comes back on `/nav_status` (state, current waypoint, distance remaining, ETA, error), the plan is drawn in the Gazebo mirror from a decimated `/nav_path_summary`, and **STOP stays live in every mode**.

**Architecture:** Three places change.

*Ground station* (no `rclpy`, no ROS types, JSON over roslibpy): `models.py` gains the `/nav_request` builder, the `/nav_status` and `/nav_path_summary` parsers, a `WaypointList`, and a pure `ViewTransform` (world ↔ pixel). `ros_client.py` gains `subscribe_nav_status`, `subscribe_nav_path_summary` and `send_nav_request`, following the existing `subscribe_*`/`send_*` shapes exactly. `ui/nav_row.py` is a new card built to the DRIVE row's established structure (Signals out, injectable confirms, pills, `set_state`/`refresh`). `ui/nav_map_view.py` is a new top-down plan canvas: click → world coordinate → appended waypoint, and it paints the rover, the waypoints and the decimated plan. `main_window.py` wires them and makes the Autonomous radio real.

*Orin* (`rover/src/navi_autonomy`): `nav_run.py` is the pure run state machine (idle → starting → running → paused → succeeded/aborted/refused) with an injected clock, the refusal rules, and the status dict — the same shape as `navi_supervisor/supervisor_state.py`, which is the pattern this repo has already proved. `path_summary.py` is the pure decimator. `goal_relay.py` is the node: `/nav_request` in; NavigateToPose goals out one waypoint at a time; `/nav_status` and `/nav_path_summary` published. Two ports keep the node testable and keep SP8's interfaces out of this plan: `nav2_goals.py` (`Nav2Goals`, the same two-method discipline as SP5's `nav2_control.py`) and `task_control.py` (`TaskControl` — `start_task` / `pause` / `resume` / `abort` / `notify_*` / `coordinator_state`), whose real implementation is **SP8's `navi_rpc` client**, bound in Task 8.

*Sim* (`sim/src/navi_sim_bringup`): `nav_path_mesh.py` turns the decimated polyline into an OBJ ribbon plus waypoint pads; `terrain_writer.py` — the one node in this repo that already owns a correct Gazebo spawn/delete discipline — draws it as a single `plan_0_0_<run>_g<N>` model; `sim_bridge` carries `/nav_path_summary` across the domain boundary.

## The wire contracts (defined here, implemented in three places)

### `/nav_request` — ground station → `goal_relay`, `std_msgs/String`, JSON

```json
{
  "action": "go",
  "run_id": "gs-1756633200123",
  "frame_id": "map",
  "waypoints": [{"x": 3.0, "y": -1.5, "yaw": null}, {"x": 8.0, "y": -1.5, "yaw": 0.0}]
}
```

| field | type | meaning |
|---|---|---|
| `action` | `"go"` \| `"pause"` \| `"resume"` \| `"abort"` | required; anything else is refused with a reason. **`go` is refused while the state is `starting`, `running` or `paused`** — the operator aborts first. A second Go must never silently replace the waypoints of a run that is already driving, and the UI's disabled button is not the authority (`ros2 topic pub`, or a second ground station, has to be refused by the rover) |
| `run_id` | string | identifies this Go; echoed in `/nav_status` and `/nav_path_summary`. Present on every action; on pause/resume/abort a `run_id` that does not match the running one is refused (a stale button press from a reconnected ground station must not abort a run it never started) |
| `frame_id` | string | always `"map"` in this build; a different value is refused |
| `waypoints` | list of `{x, y, yaw}` | required and non-empty for `"go"`, ignored otherwise. `yaw` may be `null` (or absent): then `goal_relay` faces the next waypoint, and the last waypoint keeps the heading it arrives with |

### `/nav_status` — `goal_relay` → ground station, `std_msgs/String`, JSON at 2 Hz **and on every state change**

```json
{
  "state": "running",
  "run_id": "gs-1756633200123",
  "waypoint_index": 1,
  "waypoint_count": 3,
  "distance_remaining_m": 12.4,
  "eta_s": 248.0,
  "error": "",
  "mode": "autonomous",
  "coordinator_state": "Autonomous",
  "stamp_s": 1830.5
}
```

| field | type | meaning |
|---|---|---|
| `state` | one of `idle` `starting` `running` `paused` `succeeded` `aborted` `refused` | the run state machine |
| `run_id` | string or `null` | the run this status is about |
| `waypoint_index` | int or `null` | **0-based** index of the waypoint being driven to; `null` when no run |
| `waypoint_count` | int | waypoints in the run; `0` when no run |
| `distance_remaining_m` | float or `null` | Nav2's `distance_remaining` for the active leg plus the straight-line length of every leg after it; `null` before the first feedback |
| `eta_s` | float or `null` | Nav2's `estimated_time_remaining` plus remaining legs at `NOMINAL_SPEED_MPS`; `null` before the first feedback |
| `error` | string | `""` when none. The reason for `refused` or `aborted`, verbatim on the row |
| `mode` | string or `null` | the last `/mode_status` mode `goal_relay` saw — so the row can say *why* Go was refused |
| `coordinator_state` | string or `null` | the coordinator's mission state as `TaskControl` reports it |
| `stamp_s` | float | `goal_relay`'s monotonic clock, for staleness |

### `/nav_path_summary` — `goal_relay` → ground station **and** sim, `std_msgs/String`, JSON, at most 2 Hz and only when the polyline changes

```json
{
  "run_id": "gs-1756633200123",
  "frame_id": "map",
  "stamp_s": 1830.5,
  "points": [[3.0, -1.5], [5.2, -1.4], [8.0, -1.5]],
  "waypoints": [[3.0, -1.5], [8.0, -1.5]],
  "length_m": 8.02,
  "source_points": 941
}
```

`points` is the decimated plan (Ramer–Douglas–Peucker, 0.10 m tolerance = two costmap cells, then a hard cap of **60** points reached by doubling the tolerance until it fits). `source_points` is the raw `/plan` length before decimation, so the field link cost is visible rather than guessed at. 60 points ≈ 1.1 KB of JSON at ≤ 2 Hz, against ~60 KB for a 941-pose `nav_msgs/Path`. An **empty `points` list clears the drawing** — that is how a finished or aborted run erases its plan from the Gazebo mirror and the canvas.

## Design decisions

**Nav2 is driven one waypoint at a time with `NavigateToPose`, not `FollowWaypoints`.** Three reasons, all load-bearing: `NavigateToPose` feedback carries `distance_remaining` and `estimated_time_remaining`, which §7 asks the status line to show and `FollowWaypoints` does not expose; pause/resume needs a goal that can be cancelled and re-sent from the same waypoint; and `notifyTaskFinished(TAG_WaypointReached)` needs a per-waypoint completion edge to fire on.

**`goal_relay` never changes the supervisor's mode.** The supervisor is the single authority on mode (SP5). Go is *refused* when the mode is not `autonomous`, with the reason on `/nav_status`; the NAV row's own **Autonomous** button is what sends `/mode_request`. One authority, one direction.

**Abort stops the run; it does not switch to manual.** Abort = cancel the Nav2 goal, then `TaskControl.abort()` — which in the topic-backed default publishes `{"action": "abort"}` on `/drive_command`, the abort path `bema_bridge` already implements (coordinator F7, with the `__sam__` lease dance in `BemaSession.abort`). Getting back to manual is the DRIVE row's Manual button, which already does `/mode_request manual` then `/drive_command manual` in that order. A NAV row that also flipped the mode would be a second mode authority, which is exactly what §4 exists to prevent. The Abort button's tooltip says so.

**The mode radio still selects a view source only.** `DashboardPage.mode_changed` is documented as "selects a view source and nothing else". SP11 keeps that promise: enabling the Autonomous radio shows the NAV row and the plan canvas; the `/mode_request` travels on the NAV row's Autonomous button, next to Go, where the operator can see it as a control action.

**Two gates on Go, deliberately.** The NAV row disables Go when the mode is not `autonomous` (UX), and `goal_relay` refuses it anyway (authority). The rover-side refusal is the one that matters — a ground station on an older build, or a `/nav_request` from `ros2 topic pub`, must still be refused — and it is separately tested.

### The map-click mechanism, and why it is a new widget

The ground station's "Gazebo mirror" today is **an H.264 video stream**: `navi_sim_video/sender.py` re-encodes `/sim_chase_camera/chase/image_raw` to UDP 5601 and `VideoPanel` renders the frames. Nothing publishes that camera's pose or intrinsics, so there is no honest pixel → world mapping to be had from it; inventing one would put waypoints metres from where the operator clicked and look entirely plausible doing it.

So SP11 adds **`ui/nav_map_view.py`** — a small top-down plan canvas inside the NAV card. It is ~150 lines of `QPainter`: a metre grid, the rover from `/localization/pose` (already subscribed at 5 Hz for the header readout), the waypoint list, and the decimated plan polyline. Click → world is then a pure affine transform (`models.ViewTransform`), testable without a screen. Typing coordinates stays the precise path; clicking is the fast one. **Axis convention:** world **+x is up** the screen and **+y is left**, which is the `map` frame seen from above — the operator's mental model of the rover's own axes, not a screen-coordinate rotation of them.

### The plan-drawing mechanism, and why `terrain_writer` owns it

The sim runs **Gazebo Classic** through `gazebo_ros` (`/spawn_entity`, `/delete_entity`, `/get_model_list`); it renders no `visualization_msgs/Marker`, and no marker infrastructure exists anywhere in `sim/`. The established mechanism for "geometry that appears in the mirror" is the one `terrain_mesh.py` / `obstacle_mesh.py` / `terrain_writer.py` already use: build an OBJ, write it under the Gazebo model dir, spawn a static visual-only SDF, delete the previous one.

The plan therefore becomes a **third mesh kind** in that pipeline — key `('plan', 0, 0)`, mesh prefix `plan_`, `nav_path_sdf()` — rather than a second node. `terrain_writer` is the only place in this repo with a *correct* spawn/delete discipline (bounded factory in-flight, delete confirmation against `/get_model_list`, per-run model ids, a start-up sweep for leftovers), every part of it paid for by a field failure. A second node spawning models beside it is how orphaned models get left on screen. Cost of reuse: one subscription, one `elif` in `_replace`, one alternation in `LEFTOVER_MODEL_RE`.

`/nav_path_summary` reaches the sim domain the way every other rover topic does — one more `--topic` argument to `sim_bridge` in `sim.launch.py`.

## Spec ambiguities, and the rulings

1. **§7 says "a mode chip beside the DRIVE row's chips"; SP5 already built it.** Ruled: SP11 does not add a second chip. It makes the mode *reachable* (Autonomous button → `/mode_request`) and enables the Autonomous radio. Two existing tests assert the old "not implemented" behaviour and are replaced in Task 7: `tests/test_ui_widgets.py::test_autonomous_is_present_but_cannot_be_selected` and `tests/test_main_window.py::test_autonomous_changes_nothing_because_nothing_is_built`.
2. **§7 says "add by clicking the map view"; there is no map view with world coordinates.** Ruled above: a new top-down canvas, not a fabricated projection out of the chase-camera stream. `MapRow` is a text row (save/load/clear) and is not the map view §7 means.
3. **§3 says `startNaViTask` is how the coordinator is told; §8 gives the interface to SP8.** Ruled: SP11 owns a `TaskControl` port and never names an SP8 symbol. Task 8 is the named integration checkpoint that binds SP8's real client to it, adapting if the names differ, and deletes the stopgap.
4. **Pause/Resume have no Nav2 equivalent.** Ruled: Pause = cancel the active `NavigateToPose` goal + `TaskControl.pause()` (coordinator F4), keeping the waypoint index; Resume = `TaskControl.resume()` (F5), then **wait for the coordinator to be observed in `Autonomous` again** before re-sending the goal for the *same* index — a pause has no time bound, and F10 `notifyConnected` lapsing or F4 leaving the coordinator in `Waiting` would otherwise let Resume send a goal into a rover the coordinator has not enabled. The rover stops during a pause because Nav2 stops publishing and the supervisor's 0.5 s autonomy deadman zeroes `/rover_twist` — the existing mechanism, not a new one. The cancel's own `STATUS_CANCELED` result must reach nobody: see `nav2_goals.py`'s `cancel()` contract and `NavRun`'s `state == RUNNING` guard, without which Pause aborts the run it paused.
5. **§4 rule 3 (localisation loss halts autonomy) belongs to the supervisor, not here.** Ruled: `goal_relay` does not re-implement it. When the supervisor drops out of `autonomous`, `goal_relay` sees the mode change on `/mode_status` and moves the run to `aborted` with the supervisor's own `reason` as the error — a report, not a second safety mechanism. "No automatic resume; the operator re-issues Go" falls out of that for free.

def nav_request_json(action: str, waypoints=None, run_id: str | None = None,
                     frame_id: str = "map") -> str:

        "action": action,
        "run_id": run_id,

def _safe_float(value, default=None):
    if isinstance(value, (int, float)) and not isinstance(value, bool):
        return float(value)
    return default


def parse_nav_status(payload: str):
    """A best-effort NavStatus from /nav_status's JSON.

    The same defensive stance as parse_mode_status: a field of the wrong
    type falls back to that field's default rather than raising inside a Qt
    slot while a mission is running.

    `stamp_s` is deliberately NOT carried onto NavStatus. It is
    goal_relay's monotonic clock, meaningful only as a difference against
    another reading of *that* clock, and the ground station cannot take
    one. Staleness is judged by the ground station's own monotonic() at
    the moment the message arrived (_on_nav_status), exactly as
    /drive_status and /mode_status are.
    """
    try:
        status = json.loads(payload)
    except (json.JSONDecodeError, TypeError):
        return None
    if not isinstance(status, dict):
        return None
    index = status.get("waypoint_index")
    return NavStatus(
        state=str(status.get("state", "")),
        run_id=status.get("run_id") if isinstance(status.get("run_id"), str) else None,
        waypoint_index=(int(index) if isinstance(index, int)
                        and not isinstance(index, bool) else None),
        waypoint_count=_safe_int(status.get("waypoint_count", 0)),
        distance_remaining_m=_safe_float(status.get("distance_remaining_m")),
        eta_s=_safe_float(status.get("eta_s")),
        error=str(status.get("error") or ""),
        mode=status.get("mode") if isinstance(status.get("mode"), str) else None,
        coordinator_state=(status.get("coordinator_state")
                           if isinstance(status.get("coordinator_state"), str) else None))


def _safe_points(value) -> list:
    """Every well-formed [x, y] pair, and nothing else.

    A malformed pair is dropped rather than failing the whole message: a
    plan with one bad vertex is still worth drawing, and a canvas that
    blanks itself because of one is worse than one that is short a point.
    """
    if not isinstance(value, list):
        return []
    points = []
    for item in value:
        if (isinstance(item, list) and len(item) == 2
                and all(isinstance(v, (int, float)) and not isinstance(v, bool)
                        for v in item)):
            points.append((float(item[0]), float(item[1])))
    return points


def parse_path_summary(payload: str):
    try:
        summary = json.loads(payload)
    except (json.JSONDecodeError, TypeError):
        return None
    if not isinstance(summary, dict):
        return None
    return PathSummary(
        run_id=summary.get("run_id") if isinstance(summary.get("run_id"), str) else None,
        frame_id=str(summary.get("frame_id", "map")),
        points=_safe_points(summary.get("points")),
        waypoints=_safe_points(summary.get("waypoints")),
        length_m=_safe_float(summary.get("length_m"), 0.0),
        source_points=_safe_int(summary.get("source_points", 0)))


def parse_waypoint_text(x_text: str, y_text: str, yaw_text: str = ""):
    """(Waypoint, "") or (None, reason). The reason is shown on the row."""
    try:
        x = float(str(x_text).strip())
    except (TypeError, ValueError):
        return None, f"x is not a number: {str(x_text)!r}"
    try:
        y = float(str(y_text).strip())
    except (TypeError, ValueError):
        return None, f"y is not a number: {str(y_text)!r}"
    yaw = None
    if str(yaw_text).strip():
        try:
            yaw = float(str(yaw_text).strip())
        except (TypeError, ValueError):
            return None, f"yaw is not a number: {str(yaw_text)!r}"
    if math.hypot(x, y) > MAX_WAYPOINT_RANGE_M:
        return None, (f"({x:.1f}, {y:.1f}) is beyond the "
                      f"{MAX_WAYPOINT_RANGE_M:.0f} m map")
    return Waypoint(x, y, yaw), ""


class WaypointList:
    """The operator's waypoint list, in order. No Qt: the row owns the
    widget, this owns the order - so reordering is testable without a
    screen and the row cannot drift from the list it sends."""

    def __init__(self):
        self._items: list = []

    @property
    def items(self) -> list:
        return list(self._items)

    def __len__(self) -> int:
        return len(self._items)

    def add(self, waypoint) -> None:
        self._items.append(waypoint)

    def remove(self, index: int) -> None:
        if 0 <= index < len(self._items):
            del self._items[index]

    def clear(self) -> None:
        self._items = []

    def move_up(self, index: int) -> None:
        if 0 < index < len(self._items):
            self._items[index - 1], self._items[index] = (
                self._items[index], self._items[index - 1])

    def move_down(self, index: int) -> None:
        if 0 <= index < len(self._items) - 1:
            self._items[index + 1], self._items[index] = (
                self._items[index], self._items[index + 1])


@dataclass(frozen=True)
class ViewTransform:
    """World (map frame, metres) <-> canvas pixels, seen from above.

    World +x is UP the screen and world +y is LEFT: the map frame viewed
    from above, which is the operator's mental model of the rover's own
    axes. Rotating that into screen coordinates instead would make every
    clicked waypoint arrive somewhere the operator did not point at.
    """
    centre_x: float
    centre_y: float
    metres_per_pixel: float
    width_px: int
    height_px: int

    def to_pixel(self, x: float, y: float) -> tuple:
        return (self.width_px / 2.0 - (y - self.centre_y) / self.metres_per_pixel,
                self.height_px / 2.0 - (x - self.centre_x) / self.metres_per_pixel)

    def to_world(self, px: float, py: float) -> tuple:
        return (self.centre_x + (self.height_px / 2.0 - py) * self.metres_per_pixel,
                self.centre_y + (self.width_px / 2.0 - px) * self.metres_per_pixel)

    def zoomed(self, factor: float) -> "ViewTransform":
        return ViewTransform(self.centre_x, self.centre_y,
                             self.metres_per_pixel * factor,
                             self.width_px, self.height_px)

    def centred_on(self, x: float, y: float) -> "ViewTransform":
        return ViewTransform(x, y, self.metres_per_pixel,
                             self.width_px, self.height_px)

    def resized(self, width_px: int, height_px: int) -> "ViewTransform":
        return ViewTransform(self.centre_x, self.centre_y,
                             self.metres_per_pixel, width_px, height_px)

```python
"""The plan, small enough for the field link.

Spec section 7: "the plan is drawn in the Gazebo mirror via
/nav_path_summary (decimated; the raw /plan is too heavy for the field
link)". A Nav2 plan over a 0.05 m costmap is one pose per cell - ~940 of
them over 47 m, about 60 KB as a nav_msgs/Path. This turns that into at
most MAX_POINTS vertices, roughly 1 KB of JSON.

Ramer-Douglas-Peucker rather than every-Nth-point: an any-angle Theta*
path is long straight runs joined by a few corners, and the corners are
the entire content. Dropping every second point keeps the straights and
rounds the corners - exactly backwards.

Pure Python, no ROS and no numpy: it runs on the laptop under plain
pytest (spec section 9 rung 1).
"""

import math

# Two costmap cells. Below this the deviation is smaller than the map the
# plan was computed on can represent.
TOLERANCE_M = 0.10

# Hard cap on the vertices that cross the link. Reached by doubling the
# tolerance until the polyline fits - a very wiggly plan loses detail
# rather than the link losing its budget.
MAX_POINTS = 60

FRAME_ID = "map"


def _perpendicular_distance(point, start, end) -> float:
    (px, py), (ax, ay), (bx, by) = point, start, end
    dx, dy = bx - ax, by - ay
    if dx == 0.0 and dy == 0.0:
        return math.hypot(px - ax, py - ay)
    # Twice the triangle's area over the base length.
    return abs(dy * (px - ax) - dx * (py - ay)) / math.hypot(dx, dy)


def _rdp(points, tolerance: float) -> list:
    if len(points) < 3:
        return list(points)
    worst_index, worst = 0, 0.0
    for i in range(1, len(points) - 1):
        d = _perpendicular_distance(points[i], points[0], points[-1])
        if d > worst:
            worst_index, worst = i, d
    if worst <= tolerance:
        return [points[0], points[-1]]
    left = _rdp(points[:worst_index + 1], tolerance)
    right = _rdp(points[worst_index:], tolerance)
    return left[:-1] + right


def decimate(points, tolerance: float = TOLERANCE_M,
             max_points: int = MAX_POINTS) -> list:
    """At most `max_points` vertices, ends always kept.

    Recursion depth: _rdp splits at the worst point, so the depth is
    bounded by the number of retained vertices, not by len(points) - a
    941-point plan that decimates to 6 recurses 6 deep, not 941.
    """
    points = [(float(x), float(y)) for x, y in points]
    if len(points) < 3:
        return points
    result = _rdp(points, tolerance)
    # Doubling rather than a binary search: at most ~10 rounds to go from
    # 0.10 m to the length of any plan the rover can hold, and each round
    # is linear in the points that survived the previous one.
    while len(result) > max_points:
        tolerance *= 2.0
        result = _rdp(points, tolerance)
    return result


def polyline_length(points) -> float:
    return sum(math.hypot(b[0] - a[0], b[1] - a[1])
               for a, b in zip(points, points[1:]))


def summary_payload(run_id, points, waypoints, now_s: float) -> dict:
    """The /nav_path_summary JSON body. `points` is the RAW plan; the
    decimation happens here so no caller can forget it."""
    decimated = decimate(points)
    return {
        "run_id": run_id,
        "frame_id": FRAME_ID,
        "stamp_s": float(now_s),
        "points": [[x, y] for x, y in decimated],
        "waypoints": [[float(x), float(y)] for x, y in waypoints],
        "length_m": polyline_length(decimated),
        "source_points": len(points),
    }
```

  Public surface: `state`, `on_mode_status(now, mode, reason)`, `on_coordinator_state(name)`, `on_request(now, request) -> None`, `tick(now)`, `on_goal_succeeded(now)`, `on_goal_failed(now, reason)`, `on_feedback(now, distance_remaining, eta_s)`, `take_actions() -> list[(name, payload)]`, `status(now) -> dict`, `take_changed() -> bool`.
  Behaviour is exactly what the tests above pin. Six points worth stating in the code:
  - **Ordering is the contract.** `CANCEL_GOAL` is always queued before `ABORT_TASK`/`PAUSE_TASK`: the goal must stop before the mission state is told it did, the same reasoning as `_on_stop_requested`'s e-stop-then-chassis-stop ordering on the ground station.
  - **`_refuse(reason)` never touches the waypoints.** A refused Go leaves the operator's list intact so they can fix the mode and press Go again, rather than retyping.
  - **`_refuse(reason)` never clobbers an active run.** Refusing a request that arrived *while* a run is `starting`/`running`/`paused` records the reason on `_error` and sets `_changed`, but leaves `_state`, `_run_id`, `_waypoints` and `_index` exactly as they were — the run keeps driving and `/nav_status` keeps reporting it. Only a refusal that arrives with **no** active run moves the machine to `REFUSED`. `test_a_second_go_while_a_run_is_active_is_refused_not_obeyed` and `test_a_pause_for_a_run_that_is_not_the_running_one_is_ignored` are the two that pin this; a `_refuse` that reset the run would turn a stray `ros2 topic pub` into a stopped mission.
  - **`go` is refused while a run is active.** `on_request` checks `self._state in (STARTING, RUNNING, PAUSED)` before anything else in the `go` branch and refuses with `f"a run is already {self._state}; abort it first"`. This is the rover-side half of "two gates, deliberately" — the row's disabled button is UX, this is authority.
  - **Arming requires an OBSERVED transition, never a cached value.** Queueing `START_TASK` (from a Go) or `RESUME_TASK` (from a Resume) sets `self._coordinator_state = None` and `self._armed_at = now`. `SEND_GOAL` is emitted from `tick` only once `on_coordinator_state("Autonomous")` has been called *after* that reset — a value cached from the previous run, or from a manual `/drive_command`, is not evidence that this task is armed. If `ARM_TIMEOUT_S` passes without it, the run aborts with `"coordinator did not reach Autonomous"`. Resume runs the identical path: it returns the run to `STARTING` keeping `_index`, queues `RESUME_TASK`, and waits — a coordinator that dropped to `Disconnected` or `Waiting` during an unbounded pause must not be sent a goal.
  - **Late results from superseded goals are ignored.** `on_goal_succeeded`, `on_goal_failed` and `on_feedback` return immediately unless `self._state == RUNNING`. `NavigateToPose`'s result future fires for a *cancelled* goal too (`STATUS_CANCELED`), so after a Pause or an Abort the cancel's own result arrives moments later; without this guard it would drive a paused run to `ABORTED` (making Resume unpressable) and queue a second `ABORT_TASK` after a deliberate Abort. `nav2_goals.py` drops the callbacks on `cancel()` as the first line of defence; this guard is the second, for a result already in flight.

"""What goal_relay needs from the primary's coordinator, and the stopgap

    coordinator's own __sam__ lease, then F7). Everything else logs and

    # and ground_station.models._COORDINATOR_STATES is the same seven

    _COORDINATOR_STATES = {

        4: "PrepareAutonomous", 5: "Autonomous", 6: "Waiting",
    }

        """The name for the last int seen on /drive_status, or None.

        None rather than a guess when the field is missing or is not an

        value = self._last_coordinator_state
        if isinstance(value, bool) or not isinstance(value, int):
